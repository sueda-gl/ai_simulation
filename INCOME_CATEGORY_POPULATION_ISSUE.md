# Income Category Population Issue - Analysis & Solutions

## 🔍 Problem Summary

**Configuration:**
- Price Grid: 11
- Fixed Income Categories (NFIC): 10
- **Result:** Only 7 out of 10 income categories are populated (Categories 8, 9, 10 are empty)

## 📊 Root Cause Analysis

### 1. **Category-First Income Architecture**

Your simulation uses a "Category-First" architecture where:
- All agents have an "Assigned Allowance Level" (1-5) from the copula model
- Incomes are generated by sampling from 5 percentile buckets (quintiles):
  - Level 1: 0-20th percentile → ~$5K-$14.5K
  - Level 2: 20-40th percentile → ~$14.5K-$19.4K
  - Level 3: 40-60th percentile → ~$19.4K-$25K
  - Level 4: 60-80th percentile → ~$25K-$33.5K
  - Level 5: 80-100th percentile → ~$33.5K-$99K

### 2. **Income Category Assignment**

The 10 income categories divide the **theoretical** income range into equal intervals:

| Category | Income Range | Status |
|----------|--------------|--------|
| 1 | $3,431 - $17,230 | ✅ Populated (310 agents) |
| 2 | $17,230 - $31,029 | ✅ Populated (440 agents) |
| 3 | $31,029 - $44,828 | ✅ Populated (175 agents) |
| 4 | $44,828 - $58,627 | ✅ Populated (41 agents) |
| 5 | $58,627 - $72,427 | ✅ Populated (24 agents) |
| 6 | $72,427 - $86,226 | ✅ Populated (5 agents) |
| 7 | $86,226 - $100,025 | ✅ Populated (5 agents) |
| 8 | $100,025 - $113,824 | ❌ **EMPTY** |
| 9 | $113,824 - $127,623 | ❌ **EMPTY** |
| 10 | $127,623 - $141,423 | ❌ **EMPTY** |

### 3. **The Mismatch**

**The problem:** Categories 8-10 cover income ranges ($100K-$141K) that **no agents can reach** because:
- The highest income generated was ~$99K (from Level 5 agents)
- The 80-100th percentile of your lognormal distribution only goes up to ~$99K
- But the category boundaries extend to $141K (the theoretical 99.99th percentile)

```
                                             ^^^

```

### 4. **Allowance Level → Income Category Mapping**

From the diagnostic, here's how agents map:

| Allowance Level | Maps to Income Categories |
|----------------|--------------------------|
| 1 (0-20%) | Cat 1 (200 agents), Cat 2 (110 agents) |
| 2 (20-40%) | Cat 1 (110 agents), Cat 2 (90 agents) |
| 3 (40-60%) | Cat 2 (200 agents) |
| 4 (60-80%) | Cat 2 (150 agents), Cat 3 (50 agents) |
| 5 (80-100%) | Cat 3-7 (125+41+24+5+5 = 200 agents) |

**Notice:** Only 5 allowance levels exist, but they're being spread across 7 categories. Categories 8-10 have no source of agents.

## 💡 Solutions

### **Option 1: Reduce NFIC to Match Your Data (RECOMMENDED)**

**Set NFIC = 7** (or even 5-6 for cleaner distribution)

**Why this works:**
- Ensures all categories are populated
- Matches the actual income distribution
- Cleaner consumption limit configuration
- No empty categories in results

**How to implement:**
1. On Page 1, change "Fixed Income Categories (NFIC)" from 10 to **7**
2. Update consumption limits to use 7 categories instead of 10
3. Re-run simulation

**Pro:** Simple, matches reality
**Con:** Fewer granular income levels for consumption limits

---

### **Option 2: Accept That Some Categories Will Be Empty**

Keep NFIC = 10 but understand that:
- Only categories 1-7 will be populated
- Categories 8-10 represent "theoretical high-income" ranges
- This is **expected behavior** given the 5-quintile income generation

**Pro:** More granular consumption limit options (even if some are unused)
**Con:** Confusing to see empty categories in results

---

### **Option 3: Change Income Generation (NOT RECOMMENDED)**

Modify the income generation to sample uniformly from the full 0-100% percentile range instead of using quintile buckets.

**Why NOT recommended:**
- Would break the Category-First architecture
- Would break the logical consistency between "Assigned Allowance Level" and actual income
- Would invalidate the copula-based trait correlations
- Significantly more complex implementation

---

## 🎯 Recommended Action

**Change NFIC from 10 to 7:**

1. This matches your actual data distribution
2. Ensures all categories are populated
3. Maintains the Category-First architecture
4. Provides clear, meaningful income brackets:
   - Category 1: ~$3K-$17K (Low income)
   - Category 2: ~$17K-$31K (Lower-middle income)
   - Category 3: ~$31K-$45K (Middle income)
   - Category 4: ~$45K-$59K (Upper-middle income)
   - Category 5: ~$59K-$72K (High income)
   - Category 6: ~$72K-$86K (Very high income)
   - Category 7: ~$86K-$100K (Highest income)

## 📝 Technical Notes

**Why does the theoretical range extend to $141K?**
- The category assignment code uses `PPF(0.9999)` to calculate max income
- This represents the 99.99th percentile of the lognormal distribution
- But actual agents only sample up to the 100th percentile (99.9th in practice)
- So there's a gap between the theoretical max and the practical max

**Why does this relate to Price Grid = 11?**
- By default, NFIC = Price Grid - 1
- So Price Grid = 11 → NFIC = 10
- This is just a default; NFIC can be set independently
- The issue is that NFIC = 10 is too many categories for 5 allowance levels

```python
# Calculate optimal NFIC based on actual income distribution

```

This ensures:
- At least 1 category per allowance level
- Some room for spread within the highest level (5)
- All categories will be populated
