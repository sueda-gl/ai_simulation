# Category-First Income Architecture

## Overview

This document describes the **Category-First** income generation architecture implemented in the simulation. This approach ensures logical consistency between an agent's categorical income level (`Assigned Allowance Level`) and their continuous dollar income.

## The Problem This Solves

### Previous Architecture (Broken)

Before this refactor, the simulation had two independent income-related variables:

1. **`Assigned Allowance Level`** (1-5): Generated by the `TraitEngine` copula as a correlated trait
2. **`income`** (dollar amount): Generated independently from a distribution on Page 1

This created **logical inconsistencies**:
- An agent in `Assigned Allowance Level` 5 (top 20%) could randomly receive a very low `income` ($5,000)
- An agent in `Assigned Allowance Level` 1 (bottom 20%) could randomly receive a very high `income` ($95,000)
- The `donation_default` regression used hard-coded values (12-200 scale) that didn't match the actual income distribution

### Category-First Architecture (Solution)

The new architecture establishes `Assigned Allowance Level` as the **single source of truth** and derives all income representations from it:

1. **`Assigned Allowance Level`** (1-5): The fundamental trait, generated by `TraitEngine`
2. **`actual_allowance`** (12-200 scale): Deterministically mapped from the level for regression use
3. **`income`** (large dollar scale): Stochastically drawn from the percentile bucket defined by the level

## How It Works

### Step 1: Population Generation

The `TraitEngine` (copula model) generates agents with correlated traits, including `Assigned Allowance Level` (1-5).

**Example Agent:**
```python
{
    'Assigned Allowance Level': 3,
    'Honesty_Humility': 3.5,
    'Study Program': 'CLEAM',
    'Group_experiment': 'NoSub',
    # ... other traits
}
```

### Step 2: First Income Request

When any decision module calls `get_agent_income()` for the first time:

1. **Retrieve the agent's `Assigned Allowance Level`** (e.g., 3)

2. **Generate `actual_allowance` (deterministic mapping)**:
   ```
   Level 1 → 12
   Level 2 → 32
   Level 3 → 72   ← Our example agent
   Level 4 → 128
   Level 5 → 200
   ```

3. **Identify the percentile bucket**:
   ```
   Level 1: [0th, 20th percentile]
   Level 2: [20th, 40th percentile]
   Level 3: [40th, 60th percentile]  ← Our example agent
   Level 4: [60th, 80th percentile]
   Level 5: [80th, 100th percentile]
   ```

4. **Calculate dollar boundaries** using the income distribution from Page 1:
   - Example: For a Lognormal(μ=10, σ=0.5) distribution:
     - 40th percentile = $42,100
     - 60th percentile = $58,500

5. **Draw a random income within the bucket**:
   - Random percentile: uniform(0.40, 0.60) → e.g., 0.523
   - Convert to dollars via PPF: `income = distribution.ppf(0.523)` → e.g., $47,500

6. **Cache both values** in `agent_state`:
   ```python
   agent_state['actual_allowance'] = 72.0
   agent_state['income'] = 47500.0
   ```

### Step 3: Subsequent Requests

All future calls to `get_agent_income()` or `get_actual_allowance()` return the cached values. Income is generated **once per agent**.

## Key Benefits

### 1. Logical Consistency
- An agent in a high income category **always** has a high dollar income
- An agent in a low income category **always** has a low dollar income
- No more contradictory trait combinations

### 2. Preserves Correlations
- `Assigned Allowance Level` remains a core copula trait
- Its correlations with other traits (Honesty-Humility, Study Program, etc.) are preserved
- The simulation maintains the statistical structure of the original research data

### 3. Scientific Validity
- The `donation_default` regression uses the correct 12-200 scale it was trained on
- Dollar income values are realistic and based on the configured distribution
- Both representations are derived from the same source of truth

### 4. Single Responsibility
- `income_utils.py` is the **only** module that generates income
- All decision modules call the same centralized functions
- No duplicate mapping logic scattered across files

## Technical Implementation

### Core Functions

#### `get_agent_income(agent_state, simulation_config, rng)`
- **Purpose**: Get or generate the large-scale dollar income
- **Returns**: `float` (e.g., $47,500)
- **Used by**: `disclose_documents`, `consumption_quantity`, and any decision needing dollar amounts
- **Side effect**: Generates both `income` and `actual_allowance` on first call

#### `get_actual_allowance(agent_state, simulation_config, rng)`
- **Purpose**: Get the small-scale allowance credit value
- **Returns**: `float` (12, 32, 72, 128, or 200)
- **Used by**: `donation_default` regression in "continuous mode"
- **Side effect**: Triggers full income generation if not yet done

#### `get_percentile_boundaries(sim_params)`
- **Purpose**: Calculate the dollar values for 20th, 40th, 60th, 80th percentiles
- **Returns**: `list` of 4 boundary values
- **How**: Uses `scipy.stats.ppf()` (inverse CDF) for the configured distribution

### Distribution Support

The architecture supports all three distribution types from Page 1:

1. **Lognormal**: Uses `scipy.stats.lognorm.ppf()`
2. **Generalised Gamma**: Uses `scipy.stats.gengamma.ppf()`
3. **Dagum**: Uses custom inverse CDF formula

All distributions correctly handle:
- Minimum values (location shift)
- Maximum values (clipping when specified)
- Infinite tails (via PPF for unbounded distributions)

## Usage Examples

### Example 1: Checking Discount Eligibility

```python
# disclose_documents.py
from src.decisions.income_utils import get_agent_income, get_simulation_param

def disclose_documents(agent_state, params, rng, simulation_config):
    # Get large-scale dollar income
    income = get_agent_income(agent_state, simulation_config, rng)
    
    # Compare against threshold
    threshold = get_simulation_param(simulation_config, 'discount_income_threshold', 12500.0)
    
    if income < threshold:
        # Agent qualifies for discount
        return {"disclose_documents": "Y"}
    else:
        return {"disclose_documents": "NA"}
```
